## 使用说明

这是一份面向当前架构的优先差距分析，不是完整的 ASVS 测试报告。只有下列工作全部完成后，才可以声称“依据 ASVS 5.0.0 Level 2 完成评估”：

1. 对每一条 L1/L2 要求记录通过、失败或不适用及其理由；
2. 同时保留设计、代码、配置和动态测试证据；
3. 由独立测试方复核并完成修复后的复测。

状态定义：

- **满足（代码证据）**：当前实现存在直接证据，但仍未经过独立动态测试。
- **部分满足**：只有部分路径、环境或文档满足。
- **缺口**：当前没有实现或没有足够证据。
- **已知失败**：已经观察到与要求直接冲突的结果。
- **外部验证**：主要取决于 Vercel、Neon、DNS、邮件或组织配置，代码无法单独证明。

## 非 ASVS、但密码管理器必须专项审查

- 恶意一方 JavaScript、Vercel/GitHub 管理员账号失陷和发布链攻击。
- 服务端回滚整个旧 envelope、跨版本降级与元数据未绑定问题。
- 主密码 KDF 在桌面/移动端的离线破解成本与拒绝服务平衡。
- 同一保险库同时保存网站密码与对应 TOTP 种子带来的二因素集中风险。
- 恢复密钥截图、打印、剪贴板和用户误保存风险。
- 浏览器扩展、恶意插件、剪贴板监听、内存转储和被入侵终端不在零知识能力范围内。
- 线上构建是否与被审计 commit 一致，以及如何向用户证明版本来源。
